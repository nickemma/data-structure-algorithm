# Reference

Short pages on the concepts you'll be expected to name and price.

**Use these as a dictionary, not a textbook.** Look something up when a design exposes a gap — when you couldn't explain what sharding costs, or you said "eventually consistent" without being sure what you were promising. Reading them front to back feels productive and teaches almost nothing.

- [Foundations](foundations/README.md) — scoping, system quality, scaling, CAP, relational data, caching
- [Working at scale](working-at-scale/README.md) — security, protocols, resilience, async workflows, distributed data, case studies

The quick version of all of it — every term with its **cost** attached — is the vocabulary table at the bottom of [how-to-approach.md](../how-to-approach.md). Knowing the cost is what gets scored; knowing the definition is not.
