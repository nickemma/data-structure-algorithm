# System-design roadmap

## Foundations

1. Scope the problem: functional requirements, non-functional requirements, and a data model.
2. Evaluate quality: reliability, performance, and observability.
3. Scale safely: vertical and horizontal scaling plus load balancers.
4. Understand CAP: consistency, availability, and partitions.
5. Store relational data: modelling, ACID transactions, and sharding.
6. Cache deliberately: client cache, server cache, CDNs, and invalidation.

## Working at scale

7. Secure the system: authentication, authorisation, and TLS.
8. Choose protocols: HTTP, REST, and GraphQL.
9. Build resilience: failure modes, fallbacks, and edge cases.
10. Run asynchronous work: queues, brokers, and data processors.
11. Store distributed data: non-relational models and replication.
12. Apply the ideas in complete case studies.

## A repeatable interview sequence

`Requirements → scale estimate → API/data model → high-level design → deep dive → failures/observability → trade-offs`

Use that sequence in every mock, even when the prompt feels familiar.
